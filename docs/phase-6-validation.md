# Phase 6 — Local shipping operations

Completed: 21 November 2026. SQLite remains the database; migration 007 adds customer-specific dispatch profiles and order lineage. Implementation, local validation and final CodeRabbit review are complete. The user subsequently authorized committing and pushing Phase 6. Phase 7, hosting and live carrier connections are not started.

## Use the features

Open **Dispatch planning** from the sidebar. Choose a customer and optionally search an order reference. The list contains at most 100 matching unbooked new/unprocessed orders. Customers see their own records; viewers cannot write. Staff manage rate/packing profiles and import tracking files.

- **Manual rate cards:** enter a carrier/service, destination country/postal prefix, optional pickup restriction, base INR amount, INR per chargeable kilogram, maximum weight and estimated days. Matching cards replace the default fictional services. Chargeable weight uses the greater of actual and volumetric weight per package, summed and rounded up to half a kilogram, divisor 5000. Amounts are final user-supplied estimates; no carrier contract, surcharge, duty or tax is calculated. Estimate provenance is retained in the booking snapshot.
- **Allocation:** choose lowest estimated cost, shortest estimated delivery, or balanced. Balanced adds price/minimum price and days/minimum days with equal weight; ties use cost then carrier name. Review the proposed service before confirming. A configured but nonmatching card does not establish carrier availability: the app falls back to explicitly fictional services.
- **Packing/warehouse:** exact SKU, units per box, unit weight, empty box weight, dimensions, maximum box weight, destination and optional pickup allocation. First matching active priority wins, ties by profile ID. Every SKU must match; conflicting pickups or more than 20 boxes are rejected. Preview shows the boxes and pickup; Apply validates the same plan and order revision. Capacities are supplied by staff, not inferred by a physical 3D solver; inventory is not tracked. Existing payment/weight/carrier rules remain available under Shipping rules.
- **Split:** select one unbooked order, enter quantities for the first replacement (the rest goes to the second), two unique references and measured packages. The UI accepts one package for each replacement; the normal order editor can add further packages. Both replacements must be nonempty. International declared values must sum to the original. Sources are retained as cancelled, with visible links to replacements. Transaction rollback prevents a partial split; replaying an already-transformed source is rejected.
- **Merge:** select 2–20 unbooked orders with the same customer, pickup, recipient, payment, invoice reference/date, destination currency/purpose/incoterm/description and appointment. Items/packages concatenate; declared values add. Maximum 100 item lines and 20 packages still apply. Sources are cancelled atomically and linked to the replacement. This prepares a combined order for one booking; it does not consolidate already-booked waybills or create a new legal invoice. Different invoice references remain separate orders.
- **Bulk shipping:** prepare up to 100 selected orders, review per-order services/prices and explicitly confirm. Stable request keys permit safe retry/recovery of the same batch. Failed rows do not discard successful bookings. Changed orders/pickups and expired quotes require re-preparation. All results are simulated.
- **Tracking files:** staff import CSV/TSV, maximum 1 MB/500 rows, using the downloadable header template. Preview runs the real event-ingestion path within a rolled-back savepoint, including cross-row duplicates/conflicts. Confirm saves valid rows, with a result for every row. Unique event keys prevent duplicates, and explicit time-zone offsets avoid ambiguous timestamps. Only known simulator waybills are accepted; no carrier is contacted.
- **International/appointments:** the order editor accepts a destination country and international postal/phone formats, per-item HS codes, declared currency/value, contents, purpose and incoterm. Supported declaration currencies are INR/USD/EUR/GBP/AED/SGD; order accounting remains INR. Optional appointment date/time and IANA zone are requests, not carrier confirmations. Details persist in orders and forward booking snapshots and appear on detail/print views. They are not customs filings, legal invoices or verified international serviceability.

## Migration and backup

Migration 007 is additive and preserves existing orders, users and shipments. Normal startup applies it once. New backups use the seven-migration schema. Keep Stage 5 backups with the matching Stage 5 source when restoring them, then run the upgraded app to apply migration 007. Never overwrite the active database to test a restore. Follow docs/local-release.md for backup and new-file restore commands.
